# Skill Pipeline Workflow

Chain multiple skills together into automated pipelines for complex, multi-phase tasks.

## 1. What is a Skill Pipeline?

A pipeline is a predefined sequence of skills that execute in order, with outputs from one skill feeding into the next. This ensures consistent, thorough execution of complex workflows.

## 2. Predefined Pipelines

### 🚀 Feature Development Pipeline

**Trigger:** "Run the feature pipeline for [feature name]"

```
┌─────────────────┐
│ @brainstorming  │  Design first, validate requirements
└────────┬────────┘
         │ Understanding Lock confirmed
         ▼
┌─────────────────┐
│ @unity-architect│  Architecture decisions, trade-offs
└────────┬────────┘
         │ ADR written, approach selected
         ▼
┌─────────────────┐
│ @csharp-master  │  Implementation
└────────┬────────┘
         │ Code written
         ▼
┌─────────────────┐
│ @unity-tdd-expert│ Write tests
└────────┬────────┘
         │ Tests passing
         ▼
┌─────────────────┐
│ @code-reviewer  │  Final review
└─────────────────┘
         │ "Ready to merge" verdict
         ▼
       Done ✅
```

**Gates (must pass to continue):**
- Brainstorming → Understanding Lock explicitly confirmed
- Architect → ADR saved to `.docs/adr/`
- Implementation → Code compiles without errors
- TDD → All tests pass
- Review → No 🔴 Critical issues

## 3. Pipeline Execution Rules

### Gate Enforcement

Each skill has an **exit gate**. Pipeline only continues if gate passes:

| Skill | Exit Gate |
|-------|-----------|
| `@brainstorming` | Understanding Lock confirmed by user |
| `@unity-architect` | ADR written and approach accepted |
| `@csharp-master` | Code compiles, no syntax errors |
| `@unity-tdd-expert` | All tests pass |
| `@code-reviewer` | No 🔴 Critical issues |
| `@vr-xr-specialist` | Quest performance budget met |
| `@netcode-specialist` | Server authority model validated |

### Failure Handling

If a gate fails:

1. **Pause the pipeline** — do not proceed
2. **Report the blocker** — what failed, why
3. **Offer options:**
   - Fix and retry current step
   - Go back to previous step
   - Abort pipeline

### Context Passing

Each skill receives:
- Original user request
- All outputs from previous skills
- Current pipeline state

## 4. Custom Pipeline Definition

Create your own pipeline in `.agents/pipelines/`:

```yaml
# .agents/pipelines/my-custom-pipeline.yaml
name: my-custom-pipeline
description: Custom workflow for [specific task]
trigger: "Run my custom pipeline"

steps:
  - skill: brainstorming
    gate: understanding_lock_confirmed

  - skill: csharp-master
    gate: code_compiles

  - skill: code-reviewer
    gate: no_critical_issues

  - workflow: unity-build-quest  # Can include workflows too
    gate: build_succeeds
```

|---------|-------------|
| **Consistency** | Same quality process every time |
| **Completeness** | No steps forgotten |
| **Traceability** | Clear record of decisions made |

| **Knowledge capture** | ADRs, tests, docs created along the way |

---

## 8. When to Use Pipelines

✅ **Use pipelines for:**
- New features (especially VR/multiplayer)
- Major refactoring
- Complex bug fixes
- Architecture changes

❌ **Don't use pipelines for:**
- Quick fixes (typos, small bugs)
- Documentation-only changes
- Exploratory work / research
- Single-file changes
