# Memory Profiler Advanced Analysis

Deep dive into memory leaks, garbage collection spikes, and VRAM optimization for stable gameplay.

## Prerequisites

- Unity Profiler knowledge
- RenderDoc (optional, for GPU memory)
- Memory Profiler package installed
- 1-2 weeks for analysis

// turbo-all

## Phase 1: Install Memory Profiler Tools

```bash
# Window → Package Manager
# Search: "memory-profiler"
# Install: Memory Profiler (by Unity)

# Alternatively, download RenderDoc for GPU memory analysis
# www.renderdoc.org
```

## Phase 2: Capture & Analyze Memory Snapshots

```csharp
using UnityEngine;
using UnityEngine.Profiling;

public class MemoryProfiler : MonoBehaviour {
    public void CaptureMemorySnapshot() {
        // Window → Analysis → Memory Profiler
        // Click: "Capture"
        // Wait for analysis (30 seconds to several minutes)
    }

    public void MonitorHeapSize() {
        long heapSize = Profiler.GetTotalAllocatedMemoryLong() / 1024 / 1024;
        long usedMemory = Profiler.usedHeapSizeLong / 1024 / 1024;
        Debug.Log($"Heap: {heapSize}MB, Used: {usedMemory}MB");
    }
}
```

## Phase 3: Identify Memory Leaks

1. **Capture Before/After Snapshots:**
   ```plaintext
   Test Scenario: Load Level → Play 5 minutes → Unload Level

   Snapshot 1: Initial state (50MB)
   Snapshot 2: After gameplay (120MB)
   Snapshot 3: After unload (55MB expected, >100MB = LEAK)

   Analyze: What objects weren't freed?
   ```

2. **Common Memory Leaks:**
   ```csharp
   // LEAK 1: Event listener not unsubscribed
   void OnEnable() {
       EventManager.OnPlayerDeath += HandleDeath;
   }
   void OnDestroy() {
       // MISSING: EventManager.OnPlayerDeath -= HandleDeath;
   }

   // LEAK 2: Coroutine not stopped
   void Start() {
       StartCoroutine(LoadAssetAsync()); // Never stopped!
   }

   // LEAK 3: Static references
   public static List<Enemy> allEnemies = new(); // Never cleared!

   // FIX: Clear in OnDestroy
   void OnDestroy() {
       allEnemies.Remove(this);
   }
   ```

## Phase 4: GarbageCollection Profiling

1. **Monitor GC Allocations:**
   ```csharp
   void Update() {
       // EVERY FRAME - generates garbage:
       string debug = "Position: " + transform.position; // String allocation!
       Button[] buttons = FindObjectsOfType<Button>(); // Array allocation!
       List<Enemy> enemies = new List<Enemy>(); // List allocation!

       // Instead, use cached references:
       _debug = $"Position: {transform.position}"; // One-time
       _buttons ??= FindObjectsOfType<Button>(); // Cache
       // Use pre-allocated pools for lists
   }
   ```

2. **Detect GC Spikes:**
   ```plaintext
   Profiler Window → GC Alloc tab:
   - Watch for spikes (>100KB per frame = problem)
   - Identify which script is allocating

   Common culprits:
   - LINQ queries (every frame)
   - String concatenation
   - Array/List creation in Update()
   - FindObjectsOfType() calls
   - Physics.OverlapSphere() without caching
   ```

## Phase 5: VRAM Optimization

```plaintext
Typical VRAM budgets:
- Mobile (2GB): 256-512 MB
- VR (4GB): 1GB-1.5GB
- PC (8GB+): 2-4GB

Use RenderDoc or GPU Profiler to analyze:
1. Texture VRAM (usually 60-70% of budget)
2. Mesh data (10-20%)
3. Render targets (10-15%)
4. GPU buffers (5-10%)
```

## Phase 6: Streaming & Asset Unloading

```csharp
public void OptimizeMemoryUsage() {
    // Unload unused assets every 30 seconds
    if (Time.frameCount % 1800 == 0) { // 1800 frames @ 60fps = 30 sec
        Resources.UnloadUnusedAssets();
        System.GC.Collect(); // Force GC collection
    }

    // Stream textures/meshes instead of keeping in memory
    StartCoroutine(LoadAssetsProgressively());
}

IEnumerator LoadAssetsProgressively() {
    foreach (var asset in assetsToLoad) {
        var request = Resources.LoadAsync(asset);
        yield return request;
        yield return new WaitForSeconds(0.1f); // Spread load
    }
}
```

## Verification Checklist

- [ ] Memory Profiler captures working smoothly
- [ ] No leaks detected (heap size stable after unload)
- [ ] GC allocations <100KB per frame average
- [ ] No spikes on gameplay events
- [ ] VRAM usage within budget per platform
- [ ] Streaming implemented for large assets
- [ ] Resources.UnloadUnusedAssets() called periodically

## Common Issues

| Issue | Solution |
|---|---|
| Memory grows forever | Find leak: check event subscriptions, static refs, coroutines |
| GC spike every N frames | Use object pooling instead of Instantiate/Destroy |
| VRAM full on mobile | Reduce texture resolution, use streaming, disable mipmaps |
| Low-end device crashes | Implement dynamic quality scaling, reduce target RAM |
