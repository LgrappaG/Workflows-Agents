- "Create QA plan for my VR game launch"
- "Design test cases for multiplayer features"

- "Define release criteria"

## 2. Test Strategy Overview

### Test Pyramid

```
                    ┌─────────┐
                    │  E2E    │  Few (expensive, slow)
                    │  Tests  │
                   ┌┴─────────┴┐
                   │Integration│  Some (moderate cost)
                   │   Tests   │
                  ┌┴───────────┴┐
                  │  Unit Tests  │  Many (cheap, fast)
                  └──────────────┘
```

### Test Types for Games

| Type | Coverage | When |
|------|----------|------|
| Unit Tests | Core systems, calculations | Every commit |
| Integration | System interactions | Every PR |
| Playtest | UX, fun factor, bugs | Weekly |
| Performance | FPS, memory, load times | Before milestone |
| Compatibility | Devices, platforms | Before release |
| Regression | Previous bugs | Before release |

## 9. Automated Testing Setup

```csharp
// Example: Core gameplay test
[UnityTest]
public IEnumerator Player_CanCompleteBasicGameLoop()
{
    // Load game
    SceneManager.LoadScene("MainMenu");
    yield return new WaitForSeconds(1f);

    // Start game
    var startButton = FindObjectOfType<StartButton>();
    startButton.OnClick();
    yield return new WaitForSeconds(2f);

    // Verify game started
    var player = FindObjectOfType<PlayerController>();
    Assert.IsNotNull(player);
    Assert.IsTrue(player.IsAlive);

    // Basic actions
    player.Move(Vector3.forward);
    yield return new WaitForSeconds(1f);
    Assert.AreNotEqual(Vector3.zero, player.transform.position);
}
```
