# WebGL Build Setup & Optimization

This workflow configures WebGL builds for web deployment, including compression, threading, memory management, and cross-browser compatibility optimization.

## Prerequisites

- Unity 2022 LTS with WebGL module
- Node.js 16+ (for local testing)
- Brotli compression tools (optional but recommended)
- 2GB free disk space minimum
- Target browsers: Chrome 90+, Firefox 88+, Safari 15+

## Context

WebGL builds enable playing Unity games in browsers without plugins. This workflow optimizes for fast download, memory efficiency, and compatibility across modern browsers.

// turbo-all

## Phase 1: WebGL Build Configuration

1. **Switch Build Target to WebGL:**
   ```bash
   File → Build Settings → WebGL
   - Select WebGL from Platform list
   - Player Settings → WebGL Tab
   ```

2. **Configure Compression:**
   ```plaintext
   Player Settings → Publishing Settings
   - Compression Format: Brotli (best compression, modern browsers only)
     OR
   - Compression Format: Gzip (wider compatibility)
   - Decompression Fallback: Enable
   ```

3. **Memory Configuration:**
   ```plaintext
   Player Settings → Default JavaScript Libraries
   - WebGL 2.0 with Memory growth enabled
   - Memory Size: Start with 512MB (minimum for most games)
   - Memory Growth: Allow up to 2GB
   ```

## Phase 2: Performance Optimization

1. **Graphics Settings:**
   ```plaintext
   Edit → Project Settings → Quality
   - Set WebGL-specific quality:
     - Texture Quality: Half
     - Shadow Cascades: 1
     - Anti-Aliasing: Disabled (post-process instead)
     - V Sync: Full V Sync
   ```

2. **Code Stripping:**
   ```plaintext
   Player Settings → Other Settings
   - Managed Stripping Level: High (removes unused code)
   - Strip Engine Code: Enable
   - WebGL Exceptions: Add any necessary namespaces
   ```

3. **Disk Streaming:**
   ```plaintext
   Edit → Project Settings → Editor
   - Enable "Disk Streaming" to reduce initial WASM download:
   - Configure streaming cache size: 256MB-1GB
   ```

## Phase 3: WebGL-Specific C# Settings

1. **Platform-Specific Conditional Compilation:**
   ```csharp
   #if UNITY_WEBGL
   // WebGL-specific code
   private void WebGLSpecificCode() {
       // No local file access in WebGL
       // No threading support
       // Limited to browser features
   }
   #endif
   ```

2. **Async Operations (Essential for WebGL):**
   ```csharp
   // WebGL is single-threaded, use Tasks and async/await
   public async Task LoadAssetAsync(string path) {
       var request = Resources.LoadAsync<Texture2D>(path);
       await Task.Delay(100); // Yield control to browser
   }
   ```

3. **Communication with JavaScript:**
   ```csharp
   // Call JavaScript from C#
   [DllImport("__Internal")]
   private static extern void JSSendData(string data);

   JSSendData("{\"message\": \"Hello from C#\"}");
   ```

## Phase 4: HTML Template & Hosting Setup

1. **Create Custom HTML Template:**
   ```html
   <!-- Assets/StreamingAssets/BuildLoaderTemplate.html -->
   <!DOCTYPE html>
   <html>
   <head>
       <meta charset="UTF-8">

       <canvas id="unity-canvas"></canvas>

       <script src="Build/Build.loader.js"></script>

           createUnityInstance(document.querySelector("#unity-canvas"), {
               dataUrl: "Build/Build.data.gz",
               frameworkUrl: "Build/Build.framework.js.gz",
               codeUrl: "Build/Build.wasm.gz",
               streamingAssetsUrl: "StreamingAssets",
               companyName: "YourCompany",
               productName: "Your Game",
               productVersion: "1.0",
           });
       </script>
   </body>
   </html>
   ```

2. **Cross-Origin Resource Sharing (CORS) Setup:**
   ```plaintext
   Server configuration (nginx/Apache):

   Nginx:
   add_header 'Access-Control-Allow-Origin' '*';
   add_header 'Access-Control-Allow-Methods' 'GET, POST, OPTIONS';
   add_header 'Access-Control-Allow-Headers' 'Content-Type';

   Apache:
   Header set Access-Control-Allow-Origin "*"
   ```

## Phase 5: Local Testing with Web Server

1. **Start Local HTTP Server:**
   ```bash
   # Using Python
   python -m http.server 8000

   # Using Node.js
   npx http-server -p 8000 -c-1

   # Using bash (macOS/Linux)
   python -m SimpleHTTPServer 8000
   ```

2. **Test in Browser:**
   ```bash
   # Open http://localhost:8000/Build/index.html
   # Open DevTools: F12
   # Check Console for errors
   # Profile Performance: DevTools → Performance tab
   ```

3. **Check Build Size:**
   ```bash
   ls -lh Build/
   # Watch for:
   # - Build.data.gz (scene data, typically 50-200MB)
   # - Build.wasm.gz (compiled code, typically 10-50MB)
   # - Build.framework.js.gz (runtime, typically 5-10MB)
   ```

## Phase 6: Build File Optimization

1. **Generate Optimal Build:**
   ```plaintext
   File → Build Settings → WebGL
   - Set Output Path: "WebGLBuild"
   - Development Build: Disable (for release)
   - Autoconnect Profiler: Disable (for release)
   - Build
   ```

2. **Post-Build Optimization (Optional but Recommended):**
   ```bash
   # Install compression tool
   npm install -g brotli

   # Compress WASM for better delivery
   brotli --quality 11 WebGLBuild/Build.wasm -o WebGLBuild/Build.wasm.br

   # Server must send Content-Encoding: br header
   ```

3. **Generate Source Maps for Debugging:**
   ```plaintext
   Player Settings → Development Build: Enable
   Build generates .map files for source debugging
   ```

## Phase 7: Deployment to Web Hosting

1. **Deploy to Traditional Web Host:**
   ```bash
   # Upload entire WebGLBuild folder to hosting
   scp -r WebGLBuild/* user@server:/var/www/html/game/
   ```

2. **Deploy to CDN (Recommended for Speed):**
   ```plaintext
   Recommended CDNs: Cloudflare, AWS CloudFront, Bunny CDN
   - Upload Build files to CDN
   - Create DNS CNAME pointing to CDN edge
   ```

3. **Configure Server Headers for Performance:**
   ```plaintext
   Add HTTP Headers:
   - Cache-Control: public, max-age=31536000 (for Build files)
   - Content-Encoding: gzip or br (for compression)
   - Access-Control-Allow-Origin: * (for CORS)
   ```

## Phase 8: Post-Launch Monitoring

1. **Monitor Performance Metrics:**
   - Page load time: Target <3s for 50MB build
   - Time to interactive: Target <5s
   - First contentful paint: Target <2s

2. **Cross-Browser Testing:**
   ```plaintext
   Test on:
   - Chrome (desktop, mobile)
   - Firefox (desktop, mobile)
   - Safari (macOS, iOS)
   - Edge (Windows)
   ```

3. **Set Up Analytics:**
   - Use Google Analytics for page views
   - Use Sentry for error tracking
   - Monitor WebGL context loss events

## Common Issues & Fixes

| Issue | Solution |
|-------|----------|
| "WebGL context lost" crash | Handle context restoration in OnApplicationFocus |
| Slow initial load (>10s) | Reduce build size, use async asset loading, implement streaming |
| "Out of memory" exception | Reduce memory allocation, implement streaming textures/meshes |
| Asset loading fails on mobile | Use CDN with aggressive caching, enable disk streaming |
| Mobile performance poor | Reduce draw calls, use LOD groups, disable shadows |
| CORS errors when loading assets | Check server CORS headers, use same-origin URLs |
